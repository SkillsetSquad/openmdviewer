# Security boundaries

Imported Markdown is untrusted. Rendering passes through rehype-sanitize before trusted KaTeX and heading generation. Imported MDX is treated as Markdown; components and JavaScript are never executed. Mermaid runs with strict security. HTML iframes, scripts, executable event attributes, unsafe links, and active embeds are stripped. Remote images need individual user consent. Code highlighting is generated by Shiki from escaped source.

The app has no backend, uploads, accounts, embedded credentials, analytics, or third-party runtime assets. IndexedDB is browser-local persistence, not encryption. Any trusted-origin script can access it. Browser extensions, device compromise, and deliberate clearing of site data are outside this protection boundary. Export backups regularly.

Static HTML contains a CSP; Next.js static hydration currently requires `unsafe-inline`, so this is not a nonce-based CSP. Sanitization is the key boundary for imported content. Do not add arbitrary runtime plugins or untrusted third-party scripts to the origin.

ZIP imports reject archives expanding beyond 100 MB, and individual imported files are limited to 30 MB. ZIP export paths cannot traverse parent directories. CSV exports neutralize leading formula characters. These limits are safety bounds, not performance guarantees for large workspaces.

The dependency audit on 15 October 2026 reported 11 high and 4 low findings. High findings were in development tooling dependency chains (`eslint-config-next`, `serve`, and the shadcn CLI); low findings were in the math parsing chain (`remark-math` / `rehype-katex`). The registry suggested major downgrades rather than compatible fixes. Those downgrades have not been forced. Re-run `npm audit` before release and after dependency updates; this statement is a dated observation, not a permanent assurance.

The regression suite includes script/event-attribute/unsafe-link imports, storage persistence, offline startup, and serious/critical axe checks. It does not constitute an exhaustive penetration test or full WCAG certification.

Report suspected issues privately to the SkillsetSquad repository maintainers using GitHub's security reporting capabilities when enabled. Do not post private documents, tokens, or exploit data containing personal information in public issues.
